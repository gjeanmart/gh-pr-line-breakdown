GitHub Token

Required for private repos. On public repos, omitting it works but is rate-limited to 60 API calls/hour. Stored only in your browser — never synced across devices, never included in exports, and only ever sent to api.github.com.

Which permissions does it need?

Read-only, and nothing more — the extension only reads the list of changed files of a pull request or a commit.

Fine-grained token recommended

  • Resource owner — the account or organisation that owns the repos. A token only ever reaches its owner's repos, so reviewing an organisation's PRs needs a token minted with that organisation selected (which its admins may have to approve). A token under your own account returns “repository not accessible” on every org repo.
  • Repository access — the repos you review. Public repos are readable either way.
  • Metadata → Read-only — required by GitHub, added for you.
  • Pull requests → Read-only — pull request pages.
  • Contents → Read-only — commit pages.

No Account permissions, and no write access anywhere.

Classic token

  • Public repos — no scope at all; the token only lifts your rate limit to 5,000 calls/hour.
  • Private repos — repo, which also grants write access to every repo you can reach. Prefer a fine-grained token.
  • SAML organisations — press Configure SSO on the token and authorise it for the org, or its repos stay invisible.
